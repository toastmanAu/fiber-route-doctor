# Retarget Toolkit to fnn v0.9.0-rc7 — Design (Sub-project A)

**Status:** approved design, pre-plan
**Date:** 2026-07-07
**Part of:** the "channel manager over the fleet" program (A = foundation; B = channel manager CLI+web; C = fleet bring-up). This spec covers **A only**.

## Goal

Update the local Fiber node from v0.7.1 to **v0.9.0-rc7** and retarget the existing
fiber-route-doctor toolkit so every already-shipped tool works against it. Deliverable:
node running 0.9.0-rc7, all six live smokes green, `npm test` + `npm run typecheck`
green with fixtures updated to 0.9 wire shapes.

## Why

The user wants the newest protocol features (0.9.x, actively developed) and explicitly
wants completed work tested against the new versioning. The node is currently v0.7.1
(Feb 2026). Two minor versions of breaking RPC changes sit between it and 0.9.0-rc7 —
notably v0.8.0's `peer_id`→`pubkey` / `node_id`→`pubkey` renames and a
`fiber-json-types` serialization overhaul — which will break our `Rpc*` types and the
view/model code that reads them. This must be an isolated, testable gate **before** the
channel manager (B) is designed, so B is written against 0.9's real `open_channel` /
`connect_peer` shapes and so any drift bug is unambiguously version-drift, not new code.

## Non-goals (deferred to B / C)

- Channel manager (`ChannelClient`, CLI commands, web panel) — Sub-project B.
- Biscuit operator-scope extension (`write("peers")`/`write("payments")`) — B.
- Opening real channels / funding the node / fleet bring-up — Sub-project C.
- Adopting new 0.9 features (e.g. `open_channel_with_external_funding`) — evaluated in B.

## Approach

### 1. Node update + clean data reset

- Download `fnn_v0.9.0-rc7-x86_64-linux-portable.tar.gz` from the nervosnetwork/fiber
  release.
- **Back up** `~/.fiber-dt/bin/fnn`, `~/.fiber-dt/data/`, and `~/.fiber-dt/fiber/`
  (timestamped copies) for rollback.
- Replace the binary at `~/.fiber-dt/bin/fnn`.
- **Clean data-dir reset instead of `fnn-migrate`.** The store format changed in
  v0.8.0 (channel-by-pubkey re-keying, network-actor restructure) and normally requires
  `fnn-migrate`. The node has **0 channels / 0 peers / 0 announced addresses**, so there
  is nothing worth migrating; a reset is the lower-variance path and avoids migration-tool
  risk. Reset the node store (`~/.fiber-dt/fiber/` and any stale store state) so 0.9.0-rc7
  starts fresh and regenerates its P2P identity.
- **Auth key is preserved:** `~/.fiber-dt/biscuit_private_key` / `biscuit_public_key`
  live outside the store and are untouched, so biscuit auth (and the configured
  `rpc.biscuit_public_key`) keeps working.
- **Config compatibility:** verify `~/.fiber-dt/data/config.yml` still parses under 0.9
  (check the 0.9 release/docs for new required keys; the `cors_enabled` key we rely on is
  already accepted by 0.7.1 and should remain). Adjust only if 0.9 rejects the current
  file.
- Restart `fiber-dt.service` (systemd user unit) and confirm `node_info` returns a 0.9.x
  `version`.

### 2. Fix the known RPC drift

Update `packages/core/src/types.ts`, `packages/core/src/health-types.ts`, and the
view/model code that reads these fields:

| Type | 0.7.1 → 0.9 change | Our code affected |
|---|---|---|
| `node_info` response | `node_id` → `pubkey`; `addresses` `MultiAddr[]` → `string[]` | Health |
| `Channel` (list_channels) | `peer_id` → `pubkey` | Health, Liquidity |
| `PeerInfo` (list_peers) | `peer_id` removed; `address` `MultiAddr` → `string` | Health |
| graph `NodeInfo` (graph_nodes) | `node_id` → `pubkey`; `addresses` → `string[]` | Diagnose, Map |
| `ChannelState` flags | now `"OUR_INIT_SENT \| THEIR_INIT_SENT"` SCREAMING_SNAKE, pipe-separated | Health, Liquidity state parsing |

The `fiber-json-types` overhaul also touched invoice/CCH types (snake_case enum variants,
hex-string signatures, etc.), but the toolkit does not consume those — step 4 confirms
nothing else is silently affected.

### 3. Refresh the source-of-truth corpus

Point the research corpus at `v0.9.0-rc7` so future field-name greps match the running
node: `/home/phill/ckb-wallet/research/fiber-payment-channels/raw/fiber` checked out /
refreshed to the `v0.9.0-rc7` tag. Re-verify each `Rpc*` type against the 0.9 serde
definitions in `crates/*/src/**` (the standing rule from the `fiber-rpc-wire-gotchas`
memory: trust the fnn source field names, not our own types).

### 4. Re-validate against the live node

Run the existing live-smoke harness against the updated node — each already targets a
tool:

- `npm run smoke:health` — node_info + list_channels + list_peers shapes
- `npm run smoke:liquidity` — channel liquidity snapshot
- `npm run smoke:map` — graph_nodes / graph_channels
- `npm run smoke:live` — Diagnose end-to-end (loadGraph → runDiagnosis)
- `npm run smoke:biscuit` — token mint + authed call
- `npm run smoke:wallet` — wallet/profile flow

Every smoke failure is drift to fix. Then update the **unit-test fixtures**
(`packages/core/test/**`, `apps/web/test/**` demo fixtures where they mirror wire shapes)
to the 0.9 wire format so `npm test` reflects reality rather than stale 0.7.1 shapes —
including the demo-mode `apps/web/src/demo/fixtures.json` snapshot if its `node_id` /
`peer_id` / `addresses` fields changed.

## Testing / verification

- `node_info.version` reports 0.9.x from the running service.
- All six `smoke:*` scripts exit green against `http://127.0.0.1:8231` with a node-key
  token.
- `npm test` green (fixtures updated to 0.9 shapes; no stale `node_id`/`peer_id` fixtures).
- `npm run typecheck` green across all four tsconfigs.
- Demo mode still renders (fixtures.json valid against updated types).

## Risks & mitigations

- **0.9-only drift beyond the 0.8.0 list.** 0.9.0-rc release notes weren't a clean
  breaking-changes list; additional renames may exist. Mitigation: the corpus diff (step 3)
  + live smokes (step 4) surface anything the table misses — that's the point of doing A
  as an isolated gate.
- **Config rejected by 0.9.** Mitigation: back up config; adjust to 0.9's schema if it
  fails to parse; the change set is small (rpc/fiber/ckb/services blocks).
- **Clean reset regenerates node identity.** Acceptable and intended — nothing references
  the old identity (0 announced addresses, 0 channels). Full backup retained for rollback.
- **Demo fixtures drift silently.** The captured snapshot could carry old field names and
  keep passing unit tests while diverging from the live node. Mitigation: step 4 explicitly
  re-captures / patches fixtures.json against the 0.9 node.

## Rollback

Restore the backed-up `bin/fnn` + `data/` + `fiber/`, restart `fiber-dt.service`. Revert
the toolkit type changes via git (work happens on a branch, merged only when all
verification is green).
